資料配信管理 本番反映・確認作業 引き継ぎ書


1. 現在の進捗

kiweb / kiweb2 の「資料配信管理」機能について、テストサーバーには必要な PHP / JS の実装が入っています。

テストサーバーでは、以下の状態まで確認済みです。

・admin アカウントのサイドバーから、資料一覧・資料配信管理を呼び出せる
・fulltime アカウントのサイドバーから、資料一覧を呼び出せる
・DB 実装済み
・pdf_documents / pdf_acknowledgements 作成済み
・テスト配信資料が3件登録済み
・テストサーバーでは、kiweb 用のDBを1つにまとめて運用

テストサーバーのDB名

bmynp_kiweb_test

今回の確認対象は、資料配信管理に直接関係する以下のみです。

・PDF資料一覧
・PDFビューア
・PDF実ファイル配信
・確認済み記録
・管理者によるPDF登録・公開管理
・pdf_documents / pdf_acknowledgements

ICTマニュアル、タスク配信、サイネージ、アクセスログ、管理画面全般は、今回の確認対象外です。


2. 先生にお願いしたい作業

先生にお願いしたい作業は次の3点です。

1. 本番DBに資料配信用SQLを流し込む
2. 本番環境で全体的な動作確認を行う
3. 実際の運用方針を決める

まずは作業1と作業2で、現在の実装が本番環境で問題なく動くか確認していただきたいです。

作業3の運用方針については、実際に触っていただいた上で「この運用なら使いやすい」「ここは調整したい」という点を決めていただけると、こちらで追加調整しやすいです。


3. 作業1: 本番DBにSQLを流し込む

やっていただきたいこと

本番の既存DBに、資料配信用のテーブルを追加してください。

資料配信機能は、既存のログインユーザー、ロール、権限を同じDB接続で参照します。そのため、資料配信用テーブルだけを別DBに分ける構成は想定していません。


実際に流し込むSQL

資料配信用テーブルのSQLは、以下の2ファイルです。

1. config/auth/database/pdf_documents.sql
2. config/auth/database/pdf_acknowledgements.sql

流し込み順は、必ず pdf_documents.sql → pdf_acknowledgements.sql の順にしてください。

理由は、pdf_acknowledgements が pdf_documents の id を参照する外部キーを持っているためです。先に pdf_acknowledgements.sql を流すと、参照先テーブルが存在せずエラーになる可能性があります。

なお、このSQLは phpMyAdmin から出力したテーブル作成SQLです。CREATE TABLE IF NOT EXISTS ではないため、すでに本番DBに同名テーブルが存在する場合は、そのまま再実行するとエラーになります。流し込み前に、pdf_documents / pdf_acknowledgements が未作成であることを確認してください。


追加が必要なテーブル

資料配信管理で直接使うテーブルは、主に以下の2つです。

pdf_documents

PDF資料そのものの管理情報を保存するテーブルです。

主な情報

・資料タイトル
・保存ファイル名
・元ファイル名
・配信対象
・確認ボタンが必要か
・公開中か非公開か
・登録者
・登録日時
・更新者
・更新日時

pdf_acknowledgements

利用者ごとの確認済み記録を保存するテーブルです。

主な情報

・資料ID
・ユーザーID
・確認日時
・IPアドレス
・User-Agent

重要

pdf_acknowledgements は、同じユーザーが同じ資料に対して確認記録を重複登録しないよう、document_id と user_id の組み合わせをユニークにする必要があります。


SQL流し込み前に確認してほしいこと

既存DBに以下があることを確認してください。

・users テーブル
・roles テーブル
・user_roles テーブル
・permissions / role_permissions テーブル、または管理者判定に使えるロール
・admin または administrator ロール、もしくは manage_users / manage_pdf_documents 権限

資料配信管理はログイン済みユーザーを前提に動くため、ユーザー・ロール・権限と資料配信用テーブルが同じDB内で参照できる必要があります。


SQL流し込み後に確認してほしいこと

phpMyAdmin などでSQLを流し込んだ後、以下を確認してください。

・pdf_documents テーブルが存在する
・pdf_acknowledgements テーブルが存在する
・pdf_acknowledgements に document_id + user_id のユニーク制約がある
・pdf_acknowledgements の document_id が pdf_documents.id を参照している
・管理画面からPDFを登録できる
・確認済みボタンを押したとき、pdf_acknowledgements に記録が入る


4. 作業2: 本番環境で全体的な動作確認を行う

まず確認してほしい一連の流れ

本番DBにSQLを流し込んだ後、最初に以下の流れを確認してください。

1. 管理者でログインする
2. 資料配信管理を開く
3. テスト用PDFを1つ登録する
4. 資料一覧に表示されることを確認する
5. PDFビューアでPDFを開く
6. 「確かに見ました」ボタンを押す
7. 確認済み表示になることを確認する
8. DBの pdf_acknowledgements に記録が入ったことを確認する
9. 資料を非公開にする
10. 利用者側の資料一覧から消えることを確認する
11. 再公開して、再び表示されることを確認する

この流れが通れば、資料配信管理の基本的な本番ローンチ確認はおおむね完了です。


ログイン・権限の確認

・未ログインで /kiweb/public/documents/index.php を開くと資料一覧を見られない
・未ログインで /kiweb/public/documents/file.php?id=... を開いてもPDFを取得できない
・一般ユーザーが /kiweb/public/documents/admin.php を開けない
・管理者だけが /kiweb/public/documents/admin.php を開ける
・管理者だけがPDF登録・公開/非公開切替を実行できる


資料一覧の確認

・admin アカウントで資料一覧を開ける
・fulltime アカウントで資料一覧を開ける
・配信対象外の資料が一覧に出ない
・公開中の資料だけが一覧に出る
・非公開にした資料が一覧から消える
・確認不要の資料は「確認不要」と表示される
・確認が必要で未確認の資料は「未確認」と表示される
・確認済みの資料は「確認済み」と表示される


PDFビューアの確認

・資料一覧からPDFビューアを開ける
・PDFが画面上に表示される
・ページ送りができる
・拡大・縮小ができる
・幅に合わせる、全体表示が動く
・スマホ幅でも表示が大きく崩れない
・配信対象外の資料IDを直接指定しても表示できない
・非公開資料のIDを直接指定しても表示できない


確認済み記録の確認

・確認が必要な資料に「確かに見ました」ボタンが出る
・ボタンを押すと「確認済み」になる
・DBの pdf_acknowledgements に記録が入る
・同じ資料をもう一度開いたときに確認済みとして表示される
・同じユーザー・同じ資料で確認記録が重複しない
・別ユーザーでは別の確認記録として保存される


管理者による資料登録の確認

・管理者で資料配信管理画面を開ける
・PDFファイルを登録できる
・PDF以外のファイルは登録できない
・50MBを超えるPDFは登録できない
・登録後、pdf_documents に資料情報が入る
・登録後、storage/auth/private-pdfs/ にPDF実ファイルが保存される
・登録した資料が資料一覧に表示される
・公開中の資料を非公開にできる
・非公開の資料を再公開できる


配信対象の確認

資料の配信対象は以下です。

・全員
・非常勤
・専任・社員

確認すること

・全員向け資料が admin / fulltime / 対象ユーザーに表示される
・非常勤向け資料が非常勤ユーザーに表示される
・非常勤向け資料が fulltime ユーザーに表示されない
・専任・社員向け資料が fulltime ユーザーに表示される
・専任・社員向け資料が非常勤ユーザーに表示されない
・管理者はすべての対象資料を確認できる


5. 参考: 関係する主なファイル

利用者側

public/documents/index.php

資料一覧を表示します。

public/documents/viewer.php

PDFを画面上で表示します。確認が必要な資料では「確かに見ました」ボタンも表示します。

public/documents/file.php

PDF実ファイルを配信します。PDFを直接公開せず、ログイン状態と配信対象を確認してからPDFを返します。

public/documents/ack.php

「確かに見ました」ボタンの保存処理です。pdf_acknowledgements に確認済み記録を保存します。


管理者側

public/documents/admin.php

管理者用の資料配信管理画面です。PDF登録、配信対象設定、確認ボタン要否、公開状態を管理します。

public/documents/admin-action.php

管理画面からのPOST処理です。PDF登録、公開/非公開切替を行います。


PDF保存先

storage/auth/private-pdfs/

PDF実ファイルの保存先です。

このフォルダは、ブラウザから直接PDFを見せるための場所ではありません。pdf-file.php 経由で、ログインと配信対象を確認した上で配信します。


6. 参考: おおまかなPHP連携

利用者が資料を見る流れ

ポータルのサイドバーで「資料一覧」をクリックします。

pdf-list.php が、ログイン中ユーザーのロールを確認し、そのユーザーに配信対象となっている資料だけを表示します。

資料をクリックすると pdf-viewer.php?id=資料ID が開きます。

pdf-viewer.php でも、資料が公開中か、ログイン中ユーザーが対象かを再確認します。

PDF本体は pdf-file.php?id=資料ID から読み込まれます。

pdf-file.php でも、ログイン状態と配信対象を確認した上で、storage/auth/private-pdfs/ 内のPDFを返します。


確認済み記録の流れ

確認が必要な資料の場合、PDFビューアに「確かに見ました」ボタンが表示されます。

ボタンを押すと pdf-ack.php にPOSTされます。

pdf-ack.php がログイン状態、資料の公開状態、配信対象を確認します。

問題なければ pdf_acknowledgements に確認日時を保存します。


管理者が資料を登録する流れ

管理者が pdf-admin.php を開きます。

資料タイトル、配信対象、確認ボタン要否、PDFファイルを指定して登録します。

POST先は pdf-admin-action.php です。

pdf-admin-action.php がPDFファイルを storage/auth/private-pdfs/ に保存し、資料情報を pdf_documents に登録します。

登録直後は公開中として扱われます。


7. 作業3: 運用方針を決める

現在は、こちらで「この形なら実用できそう」と考えた形で実装しています。

本番運用前に、先生側で以下を確認・決定していただけると、必要に応じて調整しやすくなります。


決めていただきたいこと

・誰が資料を登録するか
・誰が公開・非公開を切り替えるか
・配信対象を「全員」「非常勤」「専任・社員」の3区分で足りるか
・確認ボタンを必須にする資料の基準
・確認済み件数をどのように確認・活用するか
・古い資料をいつ非公開にするか
・PDFファイルの保管・バックアップ方針


調整が必要になりそうな例

・配信対象をもっと細かく分けたい
・確認済みユーザーの一覧を管理画面で見たい
・未確認者一覧を出したい
・未確認者へ通知したい
・資料の削除機能が必要
・資料タイトルや配信対象を後から編集したい
・登録済みPDFを差し替えたい

このあたりは運用方針が固まってから、必要に応じて追加実装する想定です。


8. 本番反映前の注意点

DBバックアップ

SQL流し込み前に、必ず本番DBのバックアップを取ってください。

既存DBに追加するため、既存のユーザー・ロール・権限テーブルを壊さないよう注意してください。


PDF保存フォルダ

storage/auth/private-pdfs/ に、WebサーバーのPHP実行ユーザーが書き込みできる必要があります。

PDF登録に失敗する場合は、まずこのフォルダの存在と書き込み権限を確認してください。


PHPバージョン

本番サーバーのPHPバージョンを確認してください。

一部の資料配信PHPにはPHP 8系の構文・関数が含まれています。本番がPHP 7系の場合は、事前にPHP 7互換へ調整が必要です。


PDFアップロードサイズ

画面側では50MBまでを想定しています。

ただし、PHPやWebサーバー側の upload_max_filesize、post_max_size、リクエスト制限が小さい場合、50MB未満でもアップロードに失敗する可能性があります。


直接URLアクセス

資料一覧、PDFビューア、PDF配信、確認記録、管理画面は、画面上のリンクを隠すだけでなく、PHP側でもログイン状態と権限を確認しています。

本番確認では、サイドバーからの操作だけでなく、直接URLを開いた場合の挙動も確認してください。


9. トラブル時に見るポイント

資料一覧が開かない

確認するもの

・ログイン状態
・DB接続情報
・pdf_documents テーブルの有無
・pdf_acknowledgements テーブルの有無
・PHPエラーログ


資料が一覧に出ない

確認するもの

・pdf_documents.is_active が 1 になっているか
・target_scope がログインユーザーのロールに合っているか
・ログインユーザーにロールが正しく付いているか
・管理者で見た場合に表示されるか


PDFが表示されない

確認するもの

・storage/auth/private-pdfs/ に実ファイルが存在するか
・pdf_documents.file_name と実ファイル名が一致しているか
・pdf-file.php?id=... が404や403になっていないか
・PDFファイルが壊れていないか


確認済み記録が保存されない

確認するもの

・pdf_acknowledgements テーブルが存在するか
・document_id と user_id のユニーク制約があるか
・pdf-ack.php がJSONを返しているか
・対象資料の requires_ack が 1 になっているか
・PHPエラーログ


管理画面に入れない

確認するもの

・ログインユーザーが管理者か
・admin / administrator ロールが付いているか
・manage_users または manage_pdf_documents 権限が付いているか
・pdf-admin.php 側で403になっていないか
