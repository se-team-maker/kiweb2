# kiweb PDF資料一覧・資料配信 リリース作業

作成日: 2026年6月22日

## 0. 現在の状況

PDF資料一覧は、ログインユーザーへPDFを配信し、対象者別の表示、PDF閲覧、確認記録、管理者による登録・公開管理を行う機能である。

この機能はテストサーバーだけにある新規機能ではない。2026年6月20日に取得した本番サーバーのファイル一式にも、主要なPHPファイルが配置されている。

本番版とテスト版で同一だったファイル:

- `teacher-auth/public/pdf-list.php`
- `teacher-auth/public/pdf-viewer.php`
- `teacher-auth/public/pdf-ack.php`
- `teacher-auth/public/pdf-admin.php`
- `teacher-auth/public/pdf-admin-action.php`

内容が異なるファイル:

- `teacher-auth/public/pdf-file.php`
  - テスト版にはサイネージ用の `booth.pdf` 対応が追加されている。
  - 通常の資料配信機能に関する大きな差分ではない。

したがって、PDF資料一覧は「本番へ新規リリースする」というより、**本番にある機能が実際に動作できる状態かを確認し、不足しているDB、保存領域、権限、ポータル導線を整える作業**になる。

## 1. この機能でできること

### 利用者

- 自分のロールを対象にした資料を一覧表示する。
- PDFを専用ビューアで閲覧する。
- 確認必須資料で「確かに見ました」を押す。
- 確認済み・未確認の状態を一覧で確認する。

### 管理者

- PDFをアップロードする。
- 資料タイトルと配信対象を設定する。
- 確認記録が必要か設定する。
- 資料を公開または非公開にする。
- 資料ごとの確認件数を確認する。

## 2. システムの流れ

```text
各ポータルの「資料一覧」
  ↓
pdf-list.php
  ↓ DBから対象資料と確認状態を取得
pdf_documents / pdf_acknowledgements
  ↓
pdf-viewer.php?id=資料ID
  ↓ 権限と配信対象を再確認
pdf-file.php?id=資料ID
  ↓
teacher-auth/private-pdfs/内のPDFを配信
```

確認必須資料の場合:

```text
「確かに見ました」
  ↓ POST
pdf-ack.php
  ↓
pdf_acknowledgementsへ確認日時等を保存
```

管理者による登録:

```text
pdf-admin.php
  ↓ CSRF付きPOST
pdf-admin-action.php
  ├─ private-pdfsへPDFを保存
  └─ pdf_documentsへ資料情報を登録
```

## 3. 利用者と配信対象

資料には次の配信対象を設定する。

| 設定値 | 表示対象 |
|---|---|
| `all` | 全員 |
| `parttime` | 非常勤 |
| `fulltime` | 社員 |

管理者はすべての対象資料を閲覧できる。

画面上でリンクを隠すだけではなく、`pdf-list.php`、`pdf-viewer.php`、`pdf-file.php`、`pdf-ack.php`の各処理でログイン状態と対象ロールを確認している。

## 4. リリース・確認に必要な作業

### 1. 本番DBの状態を確認する

少なくとも次のテーブルが必要である。

```text
pdf_documents
pdf_acknowledgements
```

現在のGitには、この2テーブルを新規作成するための確定版SQLが見当たらない。PHPファイルだけを再配置しても、DBテーブルがなければ一覧表示や既読保存は動作しない。

本番DBで次を確認する。

- 両テーブルが存在する
- `pdf_documents`に登録済み資料がある
- `pdf_acknowledgements`に利用者ごとの確認記録を保存できる
- `document_id`と`user_id`の組み合わせを重複させない制約がある
- 外部キーや削除時の扱いが運用に合っている

DBが存在しない場合は、現在のPHPが参照するカラムを整理してから、専用のマイグレーションを新規作成する。推測で本番DBへテーブルを作らない。

本番ZIPの`private-pdfs/`には、サイネージPDF以外の配信資料実ファイルが含まれていなかった。そのため、ZIPだけでは本番に登録済み資料があるか、DBと実ファイルが一致しているかを確認できない。

### 2. PDF保存領域を確認する

保存先:

```text
teacher-auth/private-pdfs/
```

確認事項:

- WebサーバーのPHP実行ユーザーが書き込みできる
- ブラウザからディレクトリ内のPDFへ直接アクセスできない
- `pdf-file.php`経由ではログイン済み利用者だけが取得できる
- 最大50MBのPDFアップロードをPHPとWebサーバーが受け付けられる
- バックアップ対象にPDF実ファイルを含める

GitにはPDF実ファイルを入れず、サーバー上の保存データとして管理する。

### 3. PHPバージョンを確認する

`pdf-list.php`、`pdf-viewer.php`、`pdf-file.php`には、`mixed`型、`match`、`str_contains`、`str_ends_with`等のPHP 8系構文・関数が含まれる。

本番サーバーがPHP 7系の場合、そのままでは動作しない。本番のPHPバージョンを確認し、PHP 7系を使う場合は互換修正してから反映する。

### 4. ポータル導線を決める

資料一覧を表示するポータルを決め、PC版とモバイル版の両方へ同じ導線を追加する。

参照先:

```text
/kiweb/teacher-auth/public/pdf-list.php
```

管理画面:

```text
/kiweb/teacher-auth/public/pdf-admin.php
```

`pdf-admin.php`は管理者専用であり、一般ユーザーのメニューへ表示しない。URLを直接指定された場合もPHP側で403にする。

### 5. 一連の動作をテストする

管理者でテスト用PDFを登録し、非常勤・社員・管理者で表示と確認記録を確認する。

## 7. 本番リリース手順

1. 本番のPHPバージョンを確認する。
2. 本番DBの2テーブルとカラム・制約を確認する。
3. `private-pdfs/`とDBをバックアップする。
4. テストサーバーで管理者・非常勤・社員の一連の動作を確認する。
5. 本番とテストのPHP差分を確認する。
6. 必要なファイルとポータル導線だけを反映する。
7. 本番でテスト用PDFを登録する。
8. 非常勤・社員・管理者で表示対象と確認記録を確認する。
9. テスト用PDFを非公開または削除対象として整理する。

## 8. 注意点

### DB作成SQLがGitにない

現在の最重要確認事項である。既存本番DBから構造を確認し、今後再現できるようマイグレーションをGitへ追加する必要がある。

### PDF実ファイルとDBはセット

DBだけ復旧してもPDFファイルがなければ閲覧できず、PDFファイルだけ復旧してもDBに資料情報がなければ一覧へ表示されない。バックアップと移行は必ずセットで行う。

### 公開・非公開は削除ではない

現在の管理処理は公開状態の切り替えが中心である。PDF実ファイルの削除、DB行の削除、確認履歴の削除については、運用ルールを別途決める。

### 個人情報

確認記録にはユーザーID、確認日時、IPアドレス、User-Agentを保存する。保存目的、閲覧者、保存期間を決める。

### サイネージとの共通ファイル

`pdf-viewer.php`と`pdf-file.php`は資料配信とサイネージで共用している。資料一覧の修正時にも、SK・EM・ブースのサイネージ表示を回帰確認する。
